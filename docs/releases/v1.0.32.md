# Hive 1.0.32 — Git controls, agent references, and safer recovery

## What's new

- The Git panel groups Fetch, Pull, and Push in one control with incoming and outgoing commit counts. The Git menu adds Sync, Rebase, Force Push, and pull request actions. Push confirmations stay tied to the branch and commits you reviewed, and commit message generation can be stopped.
- Press **⌘⇧C** in the editor or a diff to copy a line reference for an agent. In the Files panel, you can paste files copied in Finder into a worktree folder.
- The terminal accepts text from the macOS input method and preserves the final output of exiting processes. Closing an idle tab or pane no longer crashes Hive.
- Pipelines refresh repository information before launch, give agents time to finish emitting output before ending a step, and surface the underlying Git error when reading a base revision fails. Long run histories scroll more smoothly.
- Hive preserves readable sections of a damaged state file and retries failed saves. A second Hive instance leaves the active instance's state and editor drafts alone.
- Clicking a pull request row on an unselected worktree now selects the worktree first. Once it is selected, the row opens the request.
- The macOS About Hive dialog and native window menu actions work reliably again.
- Updated the bundled URL parsing dependency to address [RUSTSEC-2026-0592](https://rustsec.org/advisories/RUSTSEC-2026-0592.html).

## Verification

CI checks formatting, Clippy, workspace tests, licenses, and both Linux helpers before packaging the Apple Silicon build. The release checks verify Developer ID signing, Apple notarization, Gatekeeper, the archive checksum, and both Sparkle signatures.

The segmented Git control and worktree pull request selection were exercised separately in native development builds. Full Sparkle installation and relaunch, and paid-agent pipeline runs, were outside that test pass.
