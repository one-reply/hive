# Hive 1.0.15 — GitLab merge requests

## What's new

- Worktree cards now show GitLab merge requests and CI status, for GitLab.com and self-managed GitLab. Requests use their project-local `!IID`, with links to the MR and a failing pipeline.
- GitLab cards distinguish no merge request, unavailable metadata, and a missing pipeline. Unknown pipeline statuses remain pending.
- Use your existing `glab` sign-in on the project host: `glab auth login --hostname gitlab.com` or your self-managed hostname. GitHub continues to use `gh`. Hive leaves credentials with the CLI.

Hive uses each CLI's repository context, including its configured hosts and SSH aliases. If several MRs match a branch, the card reports the ambiguity rather than choosing one silently. Browser links require HTTPS. CLI prompts and pagers are disabled for both local and SSH projects.

Stable release for macOS on Apple Silicon. Settings and workspaces remain compatible; no migration or new library dependency is required.

## Verification and limits

Formatting, Clippy with warnings denied, 690 Rust tests, 26 Python tests, and the core/GPUI boundary passed. Three existing opt-in Rust tests remain ignored. Parser and routing tests cover captured GitHub/glab JSON, provider-specific empty states, pipeline outcomes, malformed data, safe links, and error preservation. A deliberately broken failed-pipeline mapping was rejected by its regression test.

The official glab 1.130.0 read a public GitLab.com MR and confirmed the no-MR response. An isolated native app with disposable repositories and CLI fixtures verified MR/CI, no-MR, self-managed URL data, and GitHub cards together. Real private/self-managed authentication, glab on an SSH host, clean-account installation, macOS 12 runtime, Keychain allow/deny, and a full Sparkle install/relaunch were not rechecked.
