# Hive 1.0.29 — Pipeline review and delivery

## What's new

- Comment on a range of added or deleted lines during acceptance and send the comments to the developer responsible. Only that lane gets a repair session. Required checks and reviews run again.
- On the next review, **Since your feedback** shows the files and lines changed in the repair round. Switch to **All changes** to see the whole task. Each acceptance criterion shows the evidence the reviewer reported or indicates that evidence is missing.
- Before opening a pull or merge request, Hive checks the worktree, its branch and the published commit against the work you accepted. Lanes sharing a worktree share one request. Reopen the run to see its request, CI status and a link to the first failing check when available.
- The launch preview shows required commands and approval steps. You can see which repository and setup command are being prepared. Unfinished launch forms survive navigation and restarts. **Run again** lets you choose the original recipe or an updated template.
- Start a single-lane **Quick fix** directly with a task and acceptance criteria. The library groups runs by which need your attention, which are running and which have finished.

## Verification

The pipeline changes passed 1,157 Rust tests and Clippy. CI built the Apple Silicon app and both Linux helpers. In a native macOS session, **Since your feedback** showed one repaired file out of a 30-file change. Hive also found an existing GitHub PR and restored the launch draft after a restart.

Live GitLab MR creation, a full run with paid agents and a Sparkle installation and relaunch were outside this verification pass.
