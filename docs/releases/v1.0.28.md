# Hive 1.0.28 — Pipeline checks and delivery

## What's new

- Required checks run before the first review. A failing check sends work back to its development lane. Reviewers see the results of passing checks, and minor findings appear as notes at acceptance.
- Repair rounds resume the developer's conversation, while **Retry** starts a new one. Hive can notify you when a run needs a decision, a step fails, or an active attempt passes 30 minutes.
- Set a setup command when starting a run. Hive copies ignored files matched by `.worktreeinclude` into a new worktree before running the command. A workflow's development lane can allow file edits where the selected CLI supports that permission.
- After accepting a run, open its worktree or prepare a pull or merge request for a branch you've pushed. Finished runs can be rerun or removed from the library.
- Drag the main window from the Pipelines header. The release also updates `ureq` and `sha2` and preserves existing review fingerprints.

## Verification

Automated tests cover checks before review, finding severity, repair and retry behavior, worktree setup, delivery, and compatibility with saved runs and review fingerprints. An isolated macOS debug launch opened a disposable project fixture and migrated its state to schema 4.

A clean macOS account, the minimum supported macOS version, Keychain denial, interactive pipeline gestures, and a full Sparkle install and relaunch were outside this verification pass.
