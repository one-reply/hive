# Hive 1.0.24 — Worktree sidebar memory and terminal links

## What's new

- Return to each worktree's Files tree with its expanded folders, scroll position, selection, and search intact while Hive stays open.
- Keep the Git/Files tab, Git section, Compare base, History commit, filter, and folded groups separately for each worktree. A removed Compare base falls back to the default. Git lists reload from the top; this memory lasts only for the current session.
- Hold Command over a terminal web link to underline it, then Command-click to open it in the default browser. Plain HTTP/HTTPS addresses and OSC 8 web hyperlinks are supported, including soft-wrapped links; other URL schemes are ignored.
- Show project header actions when hovering anywhere over the project group, and reduce the editor file toolbar's vertical padding.

## Verification and limits

Required release CI checks formatting, Clippy with warnings denied, workspace tests, the GPUI-free hive-core boundary, security and licenses, both Linux helper architectures, Python release-tool tests, and the macOS ARM64 bundle. Regression tests cover per-worktree state, Git tracking and stale Compare bases, hidden Files polling, file-operation locks, terminal links and URL scheme restrictions.

The development build was launched in an isolated profile with two repositories. Live sidebar switching and Command-click browser handoff were not verified because Accessibility and Screen Recording permissions were unavailable. A clean macOS account, minimum macOS version, live SSH, Keychain denial, and a complete Sparkle install/relaunch were not reverified.

Distribution requires Developer ID signing, Apple notarization, a stapled ticket, Gatekeeper acceptance, verified Sparkle archive/feed signatures, and downloaded-asset verification. The release uses the existing local Xcode signing workflow; hosted Apple API credentials are not configured. The maintainer's installed Hive is not replaced.
