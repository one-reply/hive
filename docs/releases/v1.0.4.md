# Hive 1.0.4 — System notifications and in-place agent launch

## What's new

- **macOS notifications for agents.** When an agent needs input or approval, finishes, or fails, Hive posts a macOS notification instead of an in-window toast. The title names the agent, project, worktree, and branch; the body shows the reason and the current task. A newer status from the same agent replaces its previous notification.
- **Click to jump to the agent.** Clicking a notification activates Hive, selects the agent's project and worktree in the sidebar, and focuses its pane. Opening the agent from the sidebar or ⌘K also removes its notification, so Notification Center keeps only agents you have not seen yet.
- **Notification setting.** **Settings → Terminal → Agent notifications** turns these notifications off. Unread markers in the sidebar and ⌘K remain available either way.
- **Agents start in place.** Choosing an agent from a pane's context menu starts it in that pane unless another agent already runs there; otherwise it opens in a new pane below. When the agent exits, the pane returns to a shell in the same directory.
- **Selection autoscroll.** Dragging a terminal selection above or below the pane scrolls through history and keeps extending the selection, faster the farther the pointer moves.

## Installation and compatibility

- Stable release for macOS on Apple Silicon only.
- Update through **Hive → Check for Updates**, or download the signed archive and SHA-256 checksum attached to this release.
- Existing projects, workspaces, and settings remain compatible. No data migration is required; the new notification setting defaults to on.
- macOS asks for notification permission the first time Hive posts one. New installations request persistent alerts; an existing installation keeps the style chosen in **System Settings → Notifications → Hive**.
- Finish active agent sessions before installing an update that restarts Hive.

## Verification

Formatting, Clippy with warnings denied, the Rust and Python test suites, security/license checks, and the core/GPUI dependency boundary passed locally. New regression tests cover the notification setting's default and round trip, notification text, agent placement from captured process tables, and selection autoscroll through history, including alternate screens.

The release follows the existing local Xcode Developer ID signing and Apple notarization route while hosted Apple API credentials are unavailable. Exact CI, signature, artifact, and distribution checks are recorded in the published notes.

Not reverified for this release: posting and clicking a macOS notification in the packaged app, the default alert style on a fresh installation, a full paid multi-agent turn, clean-account browser/Finder installation, Keychain allow/deny, the complete Sparkle install/relaunch cycle, and runtime on minimum macOS 12.0.
