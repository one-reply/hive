# Hive 1.0.31 — Acceptance evidence and independent regression tests

## What's new

- At acceptance, each criterion shows what closes it: a named passing test, your own observation, or an exception with a reason. You can send a single criterion back to QA. Evidence belongs to a lane and the reviewed revision, so a later change needs fresh evidence. The pull request for each checkout lists it.
- QA starts from the task, the plan and Hive's check results. After a repair it also receives the reason the work was returned.
- A single-lane run can require an independent regression test, written separately as a Cargo integration test or a project-local Jest or Vitest test. Hive confirms that it fails on the base commit and passes on the candidate. **Continue without this test** keeps the run going when the test can't be reproduced in the checkout. That criterion then needs other evidence.
- The Cross-repository recipe asks the planner for one shared contract. You can edit it at approval. API, Web, QA and repair sessions receive the approved text.
- A Git action could wait up to 15 minutes when a terminal pane or language server started at the same moment. Those processes no longer hold on to the command's output.

## Verification

The release source passed 1,184 Rust tests, Clippy and 26 packaging tests. Three Rust tests were marked ignored. Before the review fixes, Cargo, Jest and Vitest regression tests ran in temporary repositories, and the evidence dialog and shared-contract editor were exercised in a native session.

The **Continue without this test** dialog, Jest and Vitest in nested packages, a full pipeline run with paid agents and an end-to-end Sparkle installation and relaunch were outside this test pass.
