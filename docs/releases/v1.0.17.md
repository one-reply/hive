# Hive 1.0.17 — Connect GitHub and GitLab

## What's new

- Connect GitHub or GitLab from Settings → Git using the official browser sign-in flow. Existing CLI sign-ins are reused.
- Install missing official Apple Silicon CLIs with Install & Connect, without Homebrew or administrator access. Downloads use pinned checksums and private, atomic installation.
- Configure self-managed GitLab servers with an OAuth Application ID. Selected servers are remembered after restart.
- See compact provider cards with logos, clear account status and expandable server settings. Unavailable PR/MR cards open Git settings; successful sign-in refreshes their status.
- Cancel pending setup without affecting the other provider. Credentials stay managed by the official CLI; Hive does not save tokens in state.json.

## Verification and limits

712 Rust tests passed (3 existing opt-in tests ignored), with formatting, Clippy with warnings denied, and no GPUI dependency in hive-core. Tests cover hostname and OAuth ID validation, safe device prompts, API responses and failures, installer integrity and cancellation, saved-server compatibility, state transitions, and edited-host status.

Both pinned vendor archives were downloaded, verified and executed. Read-only checks verified existing accounts. Native QA covered both provider cards, GitHub device code and cancellation, invalid input, a self-managed fixture flow, server persistence after restart, and status icon alignment.

New live OAuth grants, a real self-managed OAuth server, SSH authentication, a clean macOS user profile, macOS 12, and a full Sparkle install/relaunch were not rechecked. Minimum-size and light-theme visual QA remain unverified. SSH projects continue to use credentials on their remote host. Self-managed browser login requires an OAuth application configured for that GitLab server.

Stable release for macOS on Apple Silicon.
