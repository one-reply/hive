# Hive 0.1.7 — Agents that work together

## What's new

- Agents in Hive terminals can now coordinate. Running `hive agent list` in any Hive terminal shows every running agent and its state. `hive agent start reviewer --kind codex --prompt "…"` opens a named helper in a pane beside the caller, or in a new tab with `--tab`, and hands it its first task.
- `hive agent send <name> "…"` types a message into another agent's prompt and submits it. The recipient sees who sent it and the exact command to reply, so a lead agent and its helpers can hold a two-way conversation. `--wait` returns once the turn the message started has finished; `hive agent wait` and `hive agent read` follow an agent's progress.
- Messages never answer a dialog for you. An agent waiting for a permission decision refuses them. Claude Code started by Hive receives messages immediately, even while it works; other agents receive them once their output pauses, and Enter is pressed only if the pasted text appeared in their prompt.
- Agents learn the commands from `hive --skill`, and Claude Code started by Hive is told about them automatically. Agent names appear in the sidebar and stay with their pane across restarts.
- Claude Code panes restored after a restart report their working, input and approval states again.
- Antigravity usage limits load for eligible plans: Hive now passes the account's project instead of reporting that the plan has no quota.

## Installation and compatibility

- macOS on Apple Silicon only; Intel Macs are unsupported.
- Update through Hive → Check for Updates, or download the signed archive attached to this release.
- Existing projects, settings, workspace layouts and recovery drafts remain compatible. Pane names are a new optional field that earlier versions ignore.
- `hive agent` works only inside Hive's local terminals. Elsewhere it explains that it is not running in a Hive terminal.
- Finish active agent sessions before installing an update that restarts Hive.

## Agent coordination limits

- Only local terminals take part; agents in SSH terminals cannot be reached yet.
- Hive sees permission dialogs only through Claude Code's hooks. For other agents, a message waits until their output pauses, which in practice is usually the end of a turn. A turn shorter than about one second may be missed by `--wait` until its timeout.
- Hive does not change agent permissions. Claude Code asks before running the `hive` command as usual, and Codex's sandbox may need your approval to reach Hive's local socket.
- `hive agent read` returns terminal text; full-screen agents expose only their current screen. Ask the agent to reply with `hive agent send` instead.
- Any program running as your user that finds the private per-launch socket can type into your agents. Message text is not logged or saved.
- There is no MCP server, no start in a new worktree and no event subscription yet.

## Verification

The published release records its exact build commit, CI results, signature and
notarization checks, and any unverified installation scenarios below. Agent
coordination was tested end to end in an isolated development build with a scripted
agent that emulates bracketed paste, Claude Code hooks and a modal dialog: starting a
named helper with a first task, messages in both directions, `--wait`, refusal
during a permission prompt, no Enter into a dialog, addressing errors, a new tab, and
restart with restored names and hooks. Real Claude Code and Codex sessions were not
messaged, to avoid model requests during release testing.
