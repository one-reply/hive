# Hive 1.0.2 — Clearer agent status and coordination

## What's new

- **Reported agent status.** Hive understands the Program Status Protocol (OSC 7501), so supporting agents can report when they are working, finished, blocked or in an error state. Reports also appear for SSH panes; agents without reports retain estimated status.
- **More reliable agent coordination.** `hive agent wait` and `send --wait` use reported state when available. A quiet interval during a reported working turn no longer counts as completion, and messages wait for agents that cannot queue input while working.
- **Helper notifications.** Agents started with `hive agent start` notify their parent when they need user input, fail or exit. Agent messages identify their source and preserve the user's responsibility for permission dialogs.
- **Interrupt a working turn.** `hive agent interrupt <target>` sends Escape only while the agent is working; it refuses approval dialogs and idle agents.
- **Start installed agents beside a terminal.** The pane context menu offers installed agent CLIs and opens them beside the selected pane.
- **Command-line reliability.** Piping Hive output into a command that closes early no longer causes a panic.

## Installation and compatibility

- Stable release for macOS on Apple Silicon only.
- Update through **Hive → Check for Updates**, or download the signed archive and SHA-256 checksum attached to this release.
- Existing projects, workspaces and settings remain compatible. No data migration is required.
- Finish active agent sessions before installing an update that restarts Hive.

## Verification

Regression coverage includes status parsing and fragmented terminal sequences, bounded report buffering, a real shell PTY support-query round trip, helper events, message delivery, startup failures and interruption rules. [PR #50](https://github.com/one-reply/hive/pull/50) also records isolated fake-agent integration checks and status reports from real agent CLIs without paid prompts.

This release uses the verified CI artifact and local Xcode Developer ID signing/notarization while App Store Connect API access remains unavailable to the current account. Hosted Apple signing is not claimed. Exact release CI, artifact, signature and distribution checks are recorded in the published notes.

Not reverified for this release: live terminal context-menu clicks, a full paid multi-agent turn, clean-account Finder/browser installation, Keychain allow/deny, the complete Sparkle install/relaunch cycle, and runtime on minimum macOS 12.0.
